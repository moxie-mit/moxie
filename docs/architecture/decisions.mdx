# Architecture Decisions & Project Status

This document records the architectural decisions made for the Moxie project and provides a clear breakdown of implemented vs planned features.

---

## Key Architecture Decisions

### 1. Monorepo Architecture (`pnpm` Workspaces)
- **Decision**: Use `pnpm` workspaces with packages contained in `apps/*`.
- **Rationale**: Keeps frontend and backend code in a single repository, ensuring consistent TypeScript versions, unified linting/formatting rules, and streamlined CI/CD pipelines while maintaining clean separation of concerns.

### 2. Frontend Framework (Next.js App Router)
- **Decision**: Next.js 16 (App Router) with React 19 and TypeScript.
- **Rationale**: Provides server-side rendering, optimized page loads, built-in routing (`src/app`), and seamless integration with `@clerk/nextjs`.

### 3. Backend Framework (NestJS)
- **Decision**: NestJS 11 with TypeScript.
- **Rationale**: Provides an enterprise-grade modular architecture (Modules, Controllers, Services), dependency injection, built-in validation via `class-validator`, and standard middleware support (`@clerk/express`).

### 4. Authentication Provider (Clerk)
- **Decision**: Clerk for authentication and identity management across both Next.js and NestJS.
- **Rationale**: Eliminates the risk of building custom password/auth management. `@clerk/nextjs` handles frontend login/signup UI, while `@clerk/express` provides token validation in NestJS `ClerkAuthGuard`.

### 5. Database & ODM (MongoDB + Mongoose)
- **Decision**: MongoDB with Mongoose object document mapper.
- **Rationale**: Schema flexibility for complex event, attendance, and certificate data, seamless NestJS integration via `@nestjs/mongoose`, and cloud hosting flexibility.

## Architectural Rules for Contributors

1. **Do Not Invent Architecture**: Do not introduce alternative state managers, CSS frameworks, or backend frameworks without team alignment.
2. **Preserve Decoupling**: Keep frontend UI state in `apps/frontend` and backend business/database logic in `apps/backend`.
3. **Strict Validation**: All incoming backend request DTOs must use `class-validator` annotations.
4. **Environment Safety**: Never hardcode secret keys or database connection strings in source code.
